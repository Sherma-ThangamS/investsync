# Phase 2 Broker Integration Plan

This phase is not implemented in MVP. It outlines the extension points for real broker connectivity.

## Adapter interface

Create broker adapters with common contract:

- `connectAccount(userId, brokerConfig)`
- `placeOrder(accountRef, order)`
- `cancelOrder(accountRef, brokerOrderId)`
- `syncPositions(accountRef)`
- `syncBalances(accountRef)`
- `webhookHandler(event)`

## Execution pipeline

1. Master order signal generated by internal engine.
2. For each active follower subscription:
   - risk check
   - sizing conversion
   - idempotency key generation
   - broker order placement
3. Persist broker acknowledgement + pending status.
4. Ingest fill events via webhook/polling reconciliation.
5. Update canonical ledgers and follower portfolio projections.

## Reconciliation and safety

- Idempotency per `(subscriptionId, masterTradeId)`
- Retry with backoff for transient broker failures
- Daily reconciliation for positions and cash
- Drift alerts for mismatch between broker and internal view

## Compliance posture

- Keep clear distinction between orchestration platform and brokerage services.
- Add jurisdiction-specific legal review before enabling live trading.
